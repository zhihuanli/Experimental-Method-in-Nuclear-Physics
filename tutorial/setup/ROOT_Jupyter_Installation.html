Installing ROOT and JupyterLab

These instructions prepare a Linux computer, or a Windows 10/11 computer using WSL2, for the Python and C++ ROOT tutorials in this course. Complete this setup before beginning any of the language or ROOT tutorials. No previous ROOT, Linux, or Jupyter experience is assumed.

ROOT is the data-analysis framework used in the course. The same ROOT libraries can be called from Python through PyROOT or used directly from C++. JupyterLab is the browser interface in which the tutorial code is entered, executed, annotated, and saved. A notebook runs through a kernel: select the Python kernel for PyROOT and the ROOT C++ kernel for C++.

The installation below uses Miniforge and a separate conda environment named root-course. ROOT, Python, and Jupyter are kept together in that environment instead of being mixed with the operating system's Python installation. The Linux and WSL instructions are therefore identical after WSL has been set up.

1. Windows: install WSL2 and Ubuntu

Windows users will run ROOT inside Ubuntu through Windows Subsystem for Linux, version 2 (WSL2). PowerShell is used only to install and inspect WSL. ROOT, conda, and Jupyter commands are entered later in the Ubuntu terminal.

Open PowerShell as Administrator: open the Start menu, search for PowerShell, right-click it, and select Run as administrator. Enter:

Administrator PowerShell

wsl --install -d Ubuntu

Restart Windows when requested. Open Ubuntu from the Start menu. The first launch completes the Linux installation and asks for a Linux user name and password. The password cursor does not move while the password is typed; this is normal. The Linux account is separate from the Windows account.

Check the WSL version from PowerShell:

PowerShell

wsl --list --verbose

The Ubuntu row should show version 2. If it shows version 1, enter:

Administrator PowerShell

wsl --set-version Ubuntu 2

From the next section onward, Windows users work in the Ubuntu terminal, not in PowerShell or Command Prompt. A prompt similar to student@computer:~$ identifies the Linux shell. Do not include the final $ when copying a command.

2. Install Miniforge on Linux or WSL

These commands apply to both native Linux and Ubuntu under WSL. They assume a Bash shell. On Ubuntu and Debian, first update the package index and install the small tools needed to download the installer:

Linux or Ubuntu terminal

sudo apt update
sudo apt install -y curl ca-certificates

sudo runs an administrative command and asks for the Linux account password. On another Linux distribution, install curl and the CA certificates with that distribution's package manager.

Download the Miniforge installer that matches the computer's processor and run it:

Linux or Ubuntu terminal

mkdir -p ~/Downloads
cd ~/Downloads
curl -L -O "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"
bash "Miniforge3-$(uname)-$(uname -m).sh"

~ means the Linux home directory. $(uname) and $(uname -m) insert the operating-system and processor names into the official installer filename. During installation:

  1. Press Enter to read the licence and continue to its end.
  2. Type yes to accept the licence.
  3. Press Enter to accept the default installation directory, normally ~/miniforge3.
  4. Type yes when asked whether conda should be initialized.

Close the terminal and open a new one. Confirm that conda is available:

conda --version

A version number indicates that the shell initialization succeeded. The base environment may appear as (base) at the left of the prompt. Disable its automatic activation; the course environment will be activated explicitly when it is needed:

conda config --set auto_activate_base false

3. Install ROOT and JupyterLab

A conda environment is an isolated collection of compatible programs and libraries. The following commands set strict channel priority, create root-course, and install ROOT, Python, JupyterLab, the classic notebook components required by JupyROOT, metakernel for the ROOT C++ kernel, and NumPy:

Linux or Ubuntu terminal

conda config --set channel_priority strict
conda create -n root-course -c conda-forge root jupyterlab notebook metakernel numpy
conda activate root-course

Conda displays the packages that will be installed and asks Proceed ([y]/n)?. Enter y. ROOT is a large framework, so downloading and creating the environment can take several minutes and require several gigabytes of free disk space.

After activation, the terminal prompt begins with (root-course). Activation changes the root, python, and jupyter commands to the versions installed together in this environment. A new terminal does not retain that activation; run conda activate root-course at the start of each work session.

Do not use sudo pip install, do not run Jupyter with sudo, and do not install a second copy of ROOT into this environment. Mixing system packages, user packages, and conda packages is a common source of an import ROOT failure.

4. Verify the installation

Activate the environment before testing it:

conda activate root-course
which root
which python
which jupyter

All three paths should contain miniforge3/envs/root-course. They need not be character-for-character identical, but they must belong to the same environment.

Check ROOT from the command line and then through Python:

root-config --version
python -c 'import ROOT; print(ROOT.gROOT.GetVersion())'

Both commands should print a ROOT version. A warning about command-line options is different from an import error and normally does not prevent ROOT from working.

List the notebook kernels:

jupyter kernelspec list

The list should contain a Python kernel, normally named python3, and a ROOT C++ kernel, normally displayed in JupyterLab as ROOT C++.

Installation check

The setup is complete when root-config --version prints a version, Python can execute import ROOT, and jupyter kernelspec list shows both Python and ROOT C++ kernels.

5. Start the first JupyterLab session

Create a directory for course work and start JupyterLab from it:

mkdir -p ~/experimental-methods
cd ~/experimental-methods
conda activate root-course
jupyter lab --no-browser

mkdir -p creates the directory if it does not already exist. cd makes it the current working directory. JupyterLab uses that location as the root of its file browser.

The terminal prints one or more addresses containing a temporary access token, for example:

http://localhost:8888/lab?token=...

Copy the complete address into a web browser. Under WSL, open it in the ordinary Windows browser. Keep the Ubuntu terminal running while JupyterLab is in use. If port 8888 is occupied, Jupyter may choose 8889 or another port; use the exact address printed in the terminal. Treat the token as a temporary password and do not post it publicly.

ROOT also provides the command root --notebook, which starts a Jupyter server with the ROOT kernels. The course instructions use jupyter lab because its Launcher and file browser expose the same Python and ROOT C++ kernels in one workspace.

6. Work with notebooks in JupyterLab

The JupyterLab workspace

The file browser is on the left. The main area contains the Launcher, notebooks, terminals, and other open documents as tabs. Click the + button above the file browser to open a Launcher. Under Notebook, selecting a kernel creates a new .ipynb file.

A notebook contains cells. A Code cell sends code to the selected kernel. A Markdown cell contains explanations, headings, equations, and links. The kernel name appears at the upper right of the notebook and determines which programming language the Code cells accept.

Create and rename a Python notebook

  1. In the Launcher, select Python 3 under Notebook.
  2. Right-click Untitled.ipynb in the file browser and select Rename.
  3. Use a descriptive name such as installation_check_python.ipynb.

Enter the following code in the first cell and run it with Shift+Enter:

import ROOT
print(f"ROOT version: {ROOT.gROOT.GetVersion()}")

import ROOT loads PyROOT. ROOT.gROOT is ROOT's global application object, and GetVersion() returns the installed ROOT version.

Check interactive ROOT graphics

Run the next two cells in order. The first enables interactive JavaScript rendering for later ROOT canvases:

%jsroot on
h = ROOT.TH1D(
    "h_install",
    "Detector-response check;Measured energy (keV);Counts",
    80,
    650.0,
    674.0,
)

rng = ROOT.TRandom3(2026)

for measurement in range(4000):
    measured_energy = rng.Gaus(661.7, 1.2)
    h.Fill(measured_energy)

c = ROOT.TCanvas("c_install", "Installation check", 800, 500)
h.Draw()
c.Draw()

This is a minimal detector-response check. A monoenergetic 661.7-keV gamma ray is measured repeatedly with a Gaussian standard deviation of 1.2 keV. It tests random-number generation, histogram filling, canvas creation, and browser rendering; it is not intended as a complete gamma-ray spectrum.

The histogram constructor uses the object name h_install, a title followed by x- and y-axis titles separated by semicolons, 80 bins, and an energy interval from 650 to 674 keV. TRandom3(2026) creates a generator with a fixed seed so that the check is reproducible. The loop represents 4000 measurements. Each call to Gaus(661.7, 1.2) returns one measured energy, and Fill increments the corresponding bin. The canvas size is 800 by 500 screen pixels. In a PyROOT notebook, the final c.Draw() asks Jupyter to display the canvas.

A peak centered near 661.7 keV should appear. With JSROOT active, toolbar controls and coordinate readout appear when the pointer is placed over the plot.

Create a ROOT C++ notebook

Open another Launcher and select ROOT C++. Rename the file installation_check_cpp.ipynb, enter the following code, and run it with Shift+Enter:

#include <iostream>
#include <TROOT.h>

std::cout << "ROOT version: "
          << gROOT->GetVersion()
          << std::endl;

#include makes the declarations from the named header available. std::cout writes text, gROOT->GetVersion() obtains the ROOT version through a pointer, and the semicolons terminate C++ statements. The C++ introductions on the course page explain these forms before they are used in the ROOT C++ tutorials.

Run cells and manage kernel state

  • Shift+Enter runs the selected cell and moves to the next cell.
  • Ctrl+Enter runs the selected cell and keeps it selected.
  • In [*] means that a Python cell is running. A number records its execution order.
  • Kernel → Interrupt Kernel stops a cell that is still running.
  • Kernel → Restart Kernel and Run All Cells clears variables and runs the notebook from top to bottom.
  • Ctrl+S saves the notebook. JupyterLab also autosaves periodically.

The kernel keeps variables created by earlier cells in memory. Running cells out of order can therefore produce a result that cannot be reproduced after reopening the file. Before considering an analysis complete, restart the kernel and run all cells from top to bottom.

A saved notebook contains its code, Markdown, and saved outputs, but it does not contain the live Python or C++ variables held by the kernel. Reopening a notebook requires executing its cells again.

Add an explanation with Markdown

Create a new cell, change its type from Code to Markdown using the toolbar menu, enter the following text, and run the cell:

## Detector-response check

The simulated peak represents a monoenergetic gamma ray measured with
finite detector resolution.

Markdown is used for the reasoning that connects code to the experimental problem. A notebook should record assumptions, units, parameter meanings, and observations as well as executable code.

End and resume a session

Save the notebook, return to the terminal in which JupyterLab is running, and press Ctrl+C. Confirm shutdown if prompted. Closing only the browser tab does not stop the server.

For later sessions, the complete startup sequence is:

conda activate root-course
cd ~/experimental-methods
jupyter lab --no-browser

Open the printed address and double-click an existing notebook in the file browser. The course tutorial pages are ordinary HTML pages and remain open in a separate browser tab. Create a notebook in JupyterLab when code needs to be executed or modified.

7. Linux and WSL files

The following shell commands are sufficient for routine navigation:

pwd                 # print the current directory
ls                  # list files in the current directory
cd ~/experimental-methods
mkdir analysis-1    # create a directory
cd ..               # move to the parent directory

On WSL, the Linux home directory and the Windows C: drive are different file systems. Windows files are visible under /mnt/c; for example, the Windows Downloads directory is normally:

/mnt/c/Users/WINDOWS-USER-NAME/Downloads

Keep files that are actively analysed with Linux programs in ~/experimental-methods. This avoids path and performance problems caused by repeatedly working across the Windows/Linux file-system boundary. From the course directory in WSL, the following command opens that Linux location in Windows File Explorer:

explorer.exe .

A relative filename in ROOT, such as data/spectrum.root, is interpreted relative to the notebook's working directory. Check that directory in a Python notebook with:

from pathlib import Path
print(Path.cwd())

Paths in Python and ROOT code are case-sensitive under Linux. Data and data are different directory names.

8. Common problems

conda: command not found

Close and reopen the terminal first. If the command is still missing and Miniforge was installed in the default location, enter:

source ~/miniforge3/etc/profile.d/conda.sh
conda init bash

Then close and reopen the terminal again.

ModuleNotFoundError: No module named 'ROOT'

The Python process usually comes from the wrong environment. In the same terminal used to start Jupyter, run:

conda activate root-course
which python
python -c 'import ROOT; print(ROOT.gROOT.GetVersion())'

Stop any Jupyter server started from another terminal, then start it again after activation.

The ROOT C++ kernel is absent

Confirm that Jupyter and ROOT come from the course environment:

conda activate root-course
which root
which jupyter
jupyter kernelspec list

If the Python check succeeds but the C++ kernel remains absent, reinstall the notebook integration in the same environment:

conda install -n root-course -c conda-forge root jupyterlab notebook metakernel

Close all running Jupyter servers, reactivate root-course, and run root --notebook once. ROOT's launcher sets the kernel search path directly.

The browser does not open or shows no server

With --no-browser, no browser is opened automatically. Copy the complete http://localhost:PORT/lab?token=... address from the terminal. To print the addresses of running servers, use:

jupyter server list

Under WSL, paste the localhost address into the Windows browser. The Ubuntu terminal must remain open.

A ROOT canvas is blank

In a Python notebook, first execute import ROOT, then execute %jsroot on. Keep the histogram and canvas in named variables and place c.Draw() at the end of the plotting cell. In a ROOT C++ notebook, execute %jsroot on before drawing.

Information to include when reporting an installation error

Run the following commands in the affected terminal and include their complete output together with the failed command and its full error message:

uname -a
conda info
conda list root
root-config --version
python --version
jupyter --version
jupyter kernelspec list

A screenshot often omits the command, the beginning of the error, or the active environment. Plain-text terminal output preserves this information.
