ROOT Tutorial II¶

Events and TTree with ROOT C++¶

Tutorial II introduces event-by-event data storage with TTree: defining branches, filling events, inspecting a tree, plotting branch expressions, and reading entries explicitly.

The sequence follows the original ROOT Tutorial II. A two-detector charged-particle telescope gives each stored variable a detector meaning.

Position of this tutorial¶

Study this tutorial after Tutorial I and before Coursework 4.2. It assumes one- and two-dimensional histograms and finite detector resolution.

The PyROOT and ROOT C++ versions use the same detector model and analysis steps. Study one version; use the other as a translation reference. Trees written by either interface can be opened by the other.

ROOT C++ is common in compiled unpackers, sorters, online systems, collaboration frameworks, and speed-sensitive event processing. This notebook uses ROOT's Cling interpreter; the same classes and branch definitions can be transferred to a macro or compiled program.

1. Events, entries, and branches¶

A detector system records several quantities produced by the same incident particle. Those quantities must remain associated during analysis. We call the complete record for one incident particle an event.

A TTree stores many events with a repeated structure. One stored event is normally one entry. A branch stores one field of every entry, such as the event number or a detector signal. Reading entry 25 loads the values belonging to event 25 across all branches; it does not read the 25th value from only one branch.

A tree is therefore not a histogram. A histogram accumulates bin counts and normally discards the individual input values. A tree retains event-level values so that new observables and selections can be constructed later.

The telescope event used here¶

Suppose a mixed light-ion sample containing p, d, t, ³He, ⁴He, and ⁶He is incident on a thin silicon ΔE detector followed by a sufficiently thick stopping E detector. The first detector measures signal[0], and the second measures the remaining energy as signal[1]. Both values belong to the same particle and must therefore be stored in the same tree entry. The material of the stopping detector is not needed for the present TTree example.

Each simulated entry contains:

  • eventID: the sequential event number;
  • A, Z: the generated particle mass and charge numbers;
  • E0: the generated incident kinetic energy in MeV;
  • signal[0]: measured energy loss in the thin detector, in MeV;
  • signal[1]: measured energy in the thick detector, in MeV.

The generated pairs (A, Z) = (1, 1), (2, 1), (3, 1), (3, 2), (4, 2), (6, 2) correspond respectively to p, d, t, ³He, ⁴He, and ⁶He. A, Z, and E0 are simulation truth. They make it possible to check the example, but ordinary experimental data do not reveal them automatically. Event selection later in the tutorial will use measured signals rather than truth labels.

Minimal detector-response model¶

The goal is to learn TTree, not to repeat a full stopping-power calculation. We therefore use the non-relativistic trend dE/dx ∝ Z²/v² and v² ∝ E₀/A to define an effective thin-detector loss

$$\Delta E_{\rm true}=K\,\frac{Z^2A}{E_0},$$

with K = 8 MeV² for this example. The remaining energy is

$$E_{\rm true}=E_0-\Delta E_{\rm true}.$$

The model assumes that the second detector stops the particle, so E_true is fully deposited there. Dead layers, energy-loss straggling, thresholds, and escaping particles are omitted. Gaussian smearing is applied separately to the two measured signals. With a common total-energy interval, the factor Z²A produces six isotope-response bands in the ΔE–E plane. This response parameterization is not a substitute for SRIM, LISE++, or a detector simulation when quantitative energy loss is required.

2. Create and fill a TTree¶

Open an output file first, then create the tree while that file is the current ROOT directory. The tree will be written to the file after all entries have been filled.

TFile *fout = new TFile("tree_telescope_cpp.root", "RECREATE");
TTree *tree_out = new TTree("telescope", "two-detector charged-particle telescope events");

Int_t eventID;
Int_t A;
Int_t Z;
Float_t E0;
Float_t signal_buffer[2];

TFile(filename, mode) creates or opens a ROOT file. RECREATE creates a new file and overwrites an existing file with the same name. Use it only for an output file that may safely be replaced.

TTree(name, title) creates an initially empty tree. telescope is the internal object name used when the tree is read later; the title is a human-readable description.

The C++ variables are memory buffers. Int_t is ROOT's 32-bit signed integer type and Float_t is ROOT's 32-bit floating-point type. signal_buffer[2] reserves two adjacent Float_t elements for every event. Declaring these variables does not yet create branches or store entries.

tree_out->Branch("eventID", &eventID, "eventID/I");
tree_out->Branch("A", &A, "A/I");
tree_out->Branch("Z", &Z, "Z/I");
tree_out->Branch("E0", &E0, "E0/F");
tree_out->Branch("signal", signal_buffer, "signal[2]/F");

The primitive-branch form used above is

tree->Branch(branch_name, memory_address, leaf_description);

The first argument is the branch name stored in the file. The second is the address from which ROOT will copy the current value when Fill() is called. The address-of operator & is therefore used for each scalar. An array name already converts to the address of its first element in this call, so signal_buffer is passed without &. The buffer name differs from the stored branch name signal; the first argument to Branch controls the name written to the file.

The third argument is a leaf list. The text before / is the leaf name, while the letter after / specifies the stored type. /I means a 32-bit signed integer and /F means a 32-bit floating-point value. In signal[2]/F, [2] declares exactly two floating-point elements per entry.

The C++ variable type and leaf-list type must agree. For example, pairing a Float_t buffer with /I would cause the same memory bytes to be interpreted as the wrong type. ROOT does not infer physical units; units must be documented in names, titles, or accompanying text.

TRandom3 rng(2026);
const Int_t n_events = 60000;
const Double_t K_loss = 8.0;  // effective constant in MeV^2

const Int_t species_A[6] = {1, 2, 3, 3, 4, 6};
const Int_t species_Z[6] = {1, 1, 1, 2, 2, 2};

for (eventID = 0; eventID < n_events; ++eventID) {
    Int_t species_index = rng.Integer(6);
    A = species_A[species_index];
    Z = species_Z[species_index];

    E0 = rng.Uniform(20.0, 80.0);
    Double_t dE_true = K_loss * Z * Z * A / E0;
    Double_t E_true = E0 - dE_true;

    Double_t sigma_dE = 0.03 + 0.04 * std::sqrt(dE_true);
    Double_t sigma_E = 0.08 + 0.015 * std::sqrt(E_true);

    signal_buffer[0] = std::max(0.0, rng.Gaus(dE_true, sigma_dE));
    signal_buffer[1] = std::max(0.0, rng.Gaus(E_true, sigma_E));

    tree_out->Fill();
}

std::cout << "Entries held in memory: "
          << tree_out->GetEntries() << std::endl;

Entries held in memory: 60000

A fixed seed makes the generated dataset reproducible. Integer(6) returns one of the integers 0 through 5 with equal probability and selects the matching elements of species_A and species_Z. Equal sampling is used only to make all six bands visible; it does not describe a production yield or natural abundance. Uniform(20.0, 80.0) supplies a common total kinetic-energy interval in MeV. Its lower limit keeps the simplified loss below the incident energy even for ⁶He. The two sigma formulas are effective detector-resolution models; they are not universal resolution laws.

The order inside the loop is essential. First update every branch buffer for one particle, then call tree_out->Fill(). Fill() copies the current contents of all connected buffers into one new tree entry. It does not fill a histogram and it does not automatically generate the next event. Reversing the order would store values from the preceding iteration.

fout->cd();
tree_out->Write();
fout->Close();

std::cout << "Created tree_telescope_cpp.root" << std::endl;

Created tree_telescope_cpp.root

fout->cd() makes the output file the current ROOT directory. Write() serializes the tree, including its branch structure and filled entries. Close() completes the file and releases the file handle. Calling Fill() alone changes the in-memory tree; it does not guarantee that the tree has been saved to disk.

The tree was created while fout was current and is normally owned by that file. Do not continue using tree_out after closing fout; reopen the file and retrieve a fresh tree pointer as shown next.

3. Reopen and inspect the tree¶

Inspection should precede analysis whenever a ROOT file is unfamiliar. Confirm the file contents, tree name, branch names, branch types, array dimensions, and number of entries before writing a long event loop.

TTree *tree_in = nullptr;

if (!fin || fin->IsZombie()) {
    std::cerr << "Could not open tree_telescope_cpp.root" << std::endl;
} else {
    fin->ls();
    fin->GetObject("telescope", tree_in);

if (!tree_in) {

TFile::Open(filename, mode) returns a file pointer. READ opens without permission to overwrite the file. !fin tests for a null pointer; a zombie file object indicates that ROOT created the object but could not open a valid ROOT file.

4. Quick analysis with TTree::Draw()¶

Draw() lets ROOT loop over entries internally. Its main form is

tree->Draw(expression, selection, drawing_option);

The expression specifies what is plotted, the selection specifies which entries are accepted, and the drawing option controls the display. This is well suited to checking branches, exploring correlations, and testing a simple cut before writing a longer loop.

c1->Clear();
tree_in->Draw("signal[1]");
c1->Draw();

With only a branch expression, ROOT creates and displays a temporary histogram. signal[1] selects the thick-detector value from the two-element branch. The automatic range and binning are useful for inspection but should not be treated as an analysis choice.

TH1F *hEres_quick_cpp = new TH1F(
    "hEres_quick_cpp",
    "Thick-detector energy;E (MeV);Counts per 0.5 MeV",
    170, 0.0, 85.0
);

tree_in->Draw("signal[1]>>hEres_quick_cpp", "", "goff");
c1->Clear();
hEres_quick_cpp->Draw();
c1->Draw();

The histogram constructor sets 170 bins from 0 to 85 MeV, giving a 0.5-MeV bin width. In expression>>histogram_name, >> tells TTree::Draw() to fill an existing named histogram. The branch expression supplies one value per accepted entry. The option goff performs the loop without drawing immediately; the histogram is then drawn explicitly. Repeating the command resets the histogram before filling. Use >>+histogram_name only when deliberate accumulation is required.

TH1F *hEtot_quick_cpp = new TH1F(
    "hEtot_quick_cpp",
    "Reconstructed total energy;#DeltaE + E (MeV);Counts per 0.5 MeV",
    170, 0.0, 85.0
);

tree_in->Draw("signal[0] + signal[1]>>hEtot_quick_cpp", "", "goff");
c1->Clear();
hEtot_quick_cpp->Draw();
c1->Draw();

A Draw() expression may contain arithmetic. Here the reconstructed total energy is

$$E_{\rm total}=\Delta E+E.$$

It is constructed from two stored observables. This illustrates an important distinction: a branch contains a recorded quantity, while a physics observable can be calculated later from several branches. In this simplified stopping-telescope model, the sum should be close to the generated E0, apart from detector smearing.

TH2F *hPID_quick_cpp = new TH2F(
    "hPID_quick_cpp",
    "Charged-particle telescope response;E (MeV);#DeltaE (MeV)",
    680, 0.0, 85.0,
    440, 0.0, 11.0
);

tree_in->Draw("signal[0]:signal[1]>>hPID_quick_cpp", "", "COLZ");
c1->Draw();

For a two-dimensional TTree::Draw() expression, ROOT uses y:x. The expression before the colon, signal[0], is placed on the y-axis; the expression after the colon, signal[1], is placed on the x-axis. This order is easy to reverse accidentally.

The TH2F constructor lists the x-axis binning first and the y-axis binning second. Here the x-axis has 680 bins over 0–85 MeV, giving 0.125 MeV per bin, while the y-axis has 440 bins over 0–11 MeV, giving 0.025 MeV per bin. The finer ΔE binning is important because the p, d, and t bands approach one another at high residual energy; a 0.05-MeV ΔE bin can merge visible structure that is still present in the simulated measurements. The sample contains 60,000 events so that the finer two-dimensional histogram remains populated. Even with fine bins, some overlap is expected from the finite detector resolution and must not be interpreted as a plotting error. COLZ represents bin contents by colour and adds a colour scale. The six visible bands arise from the different Z²A/E₀ energy-loss trends for the generated isotopes; TH2 itself does not create the separation.

TH2F *hPID_cut_cpp = new TH2F(

h_he_boundary_cpp->SetLineColor(kRed + 1);

          << n_selected_quick_cpp << std::endl;

He-like selected entries with TTree::Draw(): 29815

The selection string is evaluated separately for every entry. In terms of the plotted variables, the boundary is

$$\Delta E_{\rm boundary}(E)=2.5-0.025E.$$

TLine(x_1, y_1, x_2, y_2) draws the boundary segment from (0, 2.5) to (85, 0.375), the values given by this equation at the two ends of the displayed energy range. The TLine only makes the boundary visible; the selection is performed by the expression stored in helium_like_cut_cpp.

Events above the red line satisfy signal[0] > 2.5 - 0.025*signal[1] and form a helium-like sample; events below it are hydrogen-like in this simplified dataset. Unlike a constant threshold, the boundary changes with the thick-detector energy and follows the gap between the highest hydrogen band (t) and the lowest helium band (³He) over a wider energy interval. The numerical coefficients are chosen for this simulated response. They are neither a stopping-power law nor a transferable detector calibration.

The cut does not remove entries from tree_in; it only determines which entries fill the output histogram. It separates the two charge groups approximately but does not distinguish ³He, ⁴He, and ⁶He. A more elaborate boundary that follows an individual curved band normally uses ROOT's TCutG, a closed polygonal cut in two dimensions. TCutG is intentionally deferred to a later coursework exercise, after the event-selection logic introduced here is familiar.

TH1F *hZ_check_cpp = new TH1F(
    "hZ_check_cpp",
    "Generated Z after the linear H/He cut;Z;Entries",
    2, 0.5, 2.5
);

tree_in->Draw("Z>>hZ_check_cpp", helium_like_cut_cpp, "goff");
c1->Clear();
hZ_check_cpp->Draw();
c1->Draw();

Because this is a simulation, the hidden truth branch Z can be examined after defining the cut from measured signals. In this response model, the selected sample should consist almost entirely of Z = 2 entries. This verifies the direction and implementation of the cut; it does not establish the performance expected from a real telescope. Selecting directly on Z would use truth information that an experiment does not supply. Real charge groups can overlap because of straggling, reactions, thresholds, incomplete energy deposition, geometry, and detector resolution.

5. Read events explicitly in ROOT C++¶

TTree::Draw() is concise, but an explicit event loop is clearer when the analysis requires several derived quantities, nested conditions, counters, detector corrections, or calculations that are awkward to express as strings.

The traditional C++ pattern used by the original tutorial is:

  1. declare variables with the same types and dimensions as the branches;
  2. connect their addresses with SetBranchAddress();
  3. loop over entry indices;
  4. call GetEntry(i) to load one entry;
  5. calculate and fill analysis objects from the loaded values.
Int_t eventID_r;
Int_t A_r;
Int_t Z_r;
Float_t E0_r;
Float_t signal_r[2];

tree_in->SetBranchAddress("eventID", &eventID_r);
tree_in->SetBranchAddress("A", &A_r);
tree_in->SetBranchAddress("Z", &Z_r);
tree_in->SetBranchAddress("E0", &E0_r);
tree_in->SetBranchAddress("signal", signal_r);

SetBranchAddress(branch_name, memory_address) tells the tree where to place values when an entry is read. The branch name must match the file exactly. The receiving type and array capacity must match the stored leaf description. As during writing, scalars require &, while the array name already supplies the address of its first element.

The _r suffix distinguishes reading buffers from the earlier writing buffers. This is a naming convention, not a ROOT requirement. Reusing the same variable names carelessly in an interactive C++ notebook can cause redeclaration errors.

for (Long64_t i = 0; i < 5; ++i) {
    Long64_t bytes_read = tree_in->GetEntry(i);
    std::cout << eventID_r << "  "
              << A_r << "  "
              << Z_r << "  "
              << signal_r[0] << "  "
              << signal_r[1] << "  bytes="
              << bytes_read << std::endl;
}

0  2  1  0.29599  65.9363  bytes=24
1  6  2  7.54924  17.6063  bytes=24
2  6  2  3.4103  54.0821  bytes=24
3  2  1  0.369267  53.2156  bytes=24
4  4  2  3.30148  35.0703  bytes=24

GetEntry(i) loads entry i into all connected buffers and returns the number of bytes read. It does not return an event object. A non-positive return value indicates that no entry data were read. Entry indices use Long64_t because a tree can contain more entries than a 32-bit integer can address.

TH1F *hEtot_loop_cpp = new TH1F(
    "hEtot_loop_cpp",
    "Total energy from explicit loop;#DeltaE + E (MeV);Counts per 0.5 MeV",
    170, 0.0, 85.0
);
TH2F *hPID_loop_cpp = new TH2F(
    "hPID_loop_cpp",
    "Telescope response from explicit loop;E (MeV);#DeltaE (MeV)",
    680, 0.0, 85.0,
    440, 0.0, 11.0
);
TH1F *hSelected_loop_cpp = new TH1F(
    "hSelected_loop_cpp",
    "Thick-detector energy for He-like events;E (MeV);Counts per 0.5 MeV",
    170, 0.0, 85.0
);

Long64_t selected_entries = 0;
Long64_t n_entries = tree_in->GetEntries();

for (Long64_t i = 0; i < n_entries; ++i) {
    if (tree_in->GetEntry(i) <= 0) continue;

    Double_t dE_measured = signal_r[0];
    Double_t E_measured = signal_r[1];
    Double_t E_total = dE_measured + E_measured;

    hEtot_loop_cpp->Fill(E_total);
    hPID_loop_cpp->Fill(E_measured, dE_measured);

    Double_t dE_boundary = 2.5 - 0.025 * E_measured;
    if (dE_measured > dE_boundary) {
        hSelected_loop_cpp->Fill(E_measured);
        ++selected_entries;
    }
}

std::cout << "He-like selected entries: "
          << selected_entries << std::endl;

He-like selected entries: 29815

One entry supplies one matched pair of detector signals. The two-dimensional histogram must therefore be filled inside the same iteration with Fill(E_measured, dE_measured). Combining values from different entries would destroy the event correlation.

The loop also constructs a new observable and evaluates the same linear boundary used in TTree::Draw(). Agreement between the quick and explicit selected counts is a useful code check. The explicit loop is longer, but the calculation, selection, and error handling are now normal C++ statements rather than text interpreted by ROOT.

c2->cd(2);

c2->Draw();

Divide(2, 1) creates two horizontal pads. cd(1) and cd(2) select the pad receiving the next drawing command. The first panel shows the derived total energy; the second verifies that the explicit loop preserves the two-signal event structure.

6. Save analysis products¶

An analysis usually keeps the original event tree unchanged and writes derived histograms to a separate file. This preserves a clean distinction between input data and analysis products.

TFile *fanalysis = new TFile("telescope_analysis_cpp.root", "RECREATE");
fanalysis->cd();

hEtot_loop_cpp->Write();
hPID_loop_cpp->Write();
hSelected_loop_cpp->Write();

fanalysis->Close();
std::cout << "Created telescope_analysis_cpp.root" << std::endl;

Created telescope_analysis_cpp.root

The output file contains derived histograms, while tree_telescope_cpp.root remains the event-level input. Calling Write() explicitly avoids ambiguity about which objects should become persistent. The original tree need not be copied into every analysis file.

if (fin) fin->Close();

Close the input file only after the tree is no longer needed. Objects read from a ROOT file can be owned by that file; continuing to use them after closing it can produce invalid pointers. Histograms already written to the separate analysis file are safe on disk.

7. Scope of this tutorial¶

The original Tutorial II also introduced variable-length hit arrays and a generated multiparticle final state. Those are valid ROOT topics, but they are not required for Coursework 4.2 and introduce additional issues of multiplicity, array capacity, object ownership, and reaction kinematics. The present tutorial therefore keeps one fixed-length detector array and concentrates on the event-analysis concepts that are immediately needed.

Variable multiplicity is better introduced later with an actual detector-hit problem, normally using std::vector branches or a documented experiment-specific data class. TChain, RDataFrame, branch activation, and large-file performance are likewise later tools; none changes the basic meaning established here.

Summary¶

A TTree stores repeated event records. One entry normally represents one event, and branches store the fields of that event. When writing primitive branches in C++, variables provide memory buffers and leaf lists define the stored types and dimensions. Pass scalar addresses with &, pass a fixed array by its array name, update all buffers before each Fill(), and then call Write() to save the tree.

Use Print(), Show(), and Scan() to verify an unfamiliar tree. Use TTree::Draw() for quick expressions, correlations, and preliminary selections. For the traditional explicit C++ loop, connect receiving buffers with SetBranchAddress() and call GetEntry(i) before using their values. A cut selects entries for an output distribution; it does not delete entries from the source tree. The linear boundary used here introduces a two-variable cut; curved or irregular particle-identification regions are handled later with TCutG.

Most importantly, all detector values used together must come from the same entry. Preserving that event association is the reason TTree is central to experimental data analysis.
